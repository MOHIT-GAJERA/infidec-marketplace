QwikMart keeps configuration in three places. Knowing which is which avoids most setup problems.

| Where | What | Who can read it |
|---|---|---|
| **Environment variables** (`.env.local`, `apphosting.yaml`) | Firebase web config, functions region, emulator switch | Public — compiled into the browser |
| **Firestore `settings/public`** | App name, currency, COD / wallet / referral rules, enabled payment methods… | Public — every app reads it |
| **Firestore `settings/private_*`** | Payment secrets, SMTP password, SMS keys, Gemini key | **Super Admin and Cloud Functions only** |

You edit the last two in **Admin → System Settings**, never in code.

:::danger Never put secrets in `NEXT_PUBLIC_*` variables
Anything starting with `NEXT_PUBLIC_` is visible to every visitor. Payment secrets, SMTP passwords and API keys belong in System Settings, which stores them in `settings/private_*`.
:::

## Admin Panel variables

| Variable | Example | Notes |
|---|---|---|
| `NEXT_PUBLIC_FIREBASE_API_KEY` | `AIza…` | From the Firebase web app config |
| `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | `yourstore-1a2b3.firebaseapp.com` | |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | `yourstore-1a2b3` | |
| `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET` | `yourstore-1a2b3.firebasestorage.app` | |
| `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID` | `123456789012` | |
| `NEXT_PUBLIC_FIREBASE_APP_ID` | `1:123…:web:abc…` | |
| `NEXT_PUBLIC_FIREBASE_FUNCTIONS_REGION` | `asia-south1` | Must match the functions region |
| `NEXT_PUBLIC_USE_EMULATORS` | `false` | `true` connects to the local Emulator Suite |
| `NEXT_PUBLIC_EMULATOR_HOST` | `127.0.0.1` | Only with emulators |

For local development they live in `admin/.env.local`. For **App Hosting** the same values go in `admin/apphosting.yaml`:

```yaml title="admin/apphosting.yaml"
runConfig:
  minInstances: 0
  maxInstances: 4
  concurrency: 80
  cpu: 1
  memoryMiB: 512

env:
  - variable: NEXT_PUBLIC_FIREBASE_API_KEY
    value: AIza…
    availability: [BUILD, RUNTIME]
  - variable: NEXT_PUBLIC_FIREBASE_PROJECT_ID
    value: yourstore-1a2b3
    availability: [BUILD, RUNTIME]
  # … the other NEXT_PUBLIC_FIREBASE_* values …
  - variable: NEXT_PUBLIC_FIREBASE_FUNCTIONS_REGION
    value: asia-south1
    availability: [BUILD, RUNTIME]
  - variable: NEXT_PUBLIC_USE_EMULATORS
    value: "false"
    availability: [BUILD, RUNTIME]
```

## Mobile apps

The apps read their Firebase configuration from `lib/firebase_options.dart` and `android/app/google-services.json`, generated by `flutterfire configure`. See [Customer App → Firebase Setup](doc:app-customer/firebase-setup).

## Functions region

All Cloud Functions run in `asia-south1` (Mumbai). To use another region (for example `europe-west1`):

1. `firebase/functions/src/shared/firebase.ts` → `export const REGION = 'europe-west1';`
2. Admin Panel → `NEXT_PUBLIC_FIREBASE_FUNCTIONS_REGION=europe-west1`; Web Portal → `web/src/lib/firebase.ts` → `export const FUNCTIONS_REGION = 'europe-west1';`
3. Both Flutter apps → `lib/core/config.dart` → `functionsRegion`
4. Deploy the functions again and rebuild every client.

:::warning
A client that calls the wrong region fails with *"not-found"* or *"internal"* errors on every action (add to cart, place order). Keep all four places in sync.
:::
